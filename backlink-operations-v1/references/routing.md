# Execution-lane routing

Routing decides which execution instructions to load; it is not stored as a record type.

- Directory lane: product/software/startup/app/AI-tool submission or listing form.
- Article lane: Blogger, Dev.to, Hashnode, Substack, Medium, or another legitimate long-form editor.
- Social lane: Pinterest Pin, X/LinkedIn short post, image/link post, or thread.

Confirm the route from the live page. A homepage alone is not enough. Profile-link edits, forum replies, comments, fake engagement, irrelevant promotion, paid-link routes, and forced reciprocal links remain unsupported.

All admitted lanes write one Placement. The `route` string preserves the usable entry path without keeping a separate type field.

The user-selected free badge alternative to a free waiting plan is an explicit exception to the forced-reciprocal exclusion. Apply the pricing and badge queue rules in `../../submit-product-directories-v1-batch/references/status-model.md`: record all plans in Cost Detail, set reciprocal requirement to `required`, queue `waiting badge`, and leave without submitting. Skip these rows in ordinary batches; resume only in the later authorized badge-processing batch after verifying the badge.
